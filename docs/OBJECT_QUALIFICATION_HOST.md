# Private saved Object samples

**Source only, inactive and undeployed.** The [owned sample store](../community/object_qualification_store.py),
[loopback host](../community/object_qualification_host.py) and dedicated
[private bridge](../deploy/cloudflare/object-qualification-bridge/worker.js) connect
the saved numerical adapter to the [account registry](OBJECT_ACCOUNT_QUALIFICATION.md).
They do not run models, retrieve images, create contributions or credit, or open
Object assignments. No listener, startup task, binding, secret or transfer is
installed by these modules. The operational hold remains.

## Approved delivery

`deliver_owned_sample` makes a finite **local file copy** into an owned private
folder outside the checkout. It is not an R2 downloader or public upload API.
Actual external transfer still requires the pending destination-specific approval
and an approved transport. The operator must supply a separately pinned approval
record after obtaining legitimate consent; this code never grants that consent.
All approval records generated by the tests are explicitly synthetic.

The sealed package identifies account, immutable request, complete profile,
artifact-set digest and numerical policy digest. Its exact inventory contains
the saved artifact manifest, detector submission, index manifest, separately
saved execution-identity receipt and all referenced index files. Only listed
files are copied. Missing, unrelated, duplicate, case-colliding, linked, escaping
or Windows device paths fail validation. Inventory digests and sizes are checked;
at most 96 files / 40 MiB are allowed per sample.

The independent approval pins that exact package, owner/request/profile/policy,
source folder and destination folder, with at most 30 days of validity. Checksums
or an uploader's approval flag cannot create permission. Source and destination
must be separate private directories. No request selects a filesystem path.
OS access controls for those directories and operator records remain an actual
setup requirement; a checksum does not establish who wrote a file.

A shared OS writer lock prevents simultaneous imports exceeding the store bound.
At most 32 retained entries are allowed, including failed partial copies. Import
uses a deterministic job ID, exclusive files and an atomic directory rename.
A failed `.partial-…` remains private and blocks automatic retry or overwrite.
An existing completed job is never overwritten. There is no automatic deletion
or disk cleanup that could erase original runs or failures.

The resulting delivery receipt pins the package and approval. **It is not a saved
execution receipt or a qualification decision.** Import does not write the trusted
catalog. The operator separately installs and pins a bounded catalog of owned
delivery receipts under the same numerical policy and confirmed Community resource.

## Private lookup and comparison

`OwnedObjectQualificationStore` receives an already constructed, pinned combined
comparator plus the private root and independently pinned catalog. It resolves
only the job ID derived from account/request/profile/artifact identity. Both
delivery receipt and package must match the request, policy, root and validity.
Arbitrary paths, another account's files and client approval flags are refused.

Every lookup rechecks the catalog, private delivery receipt and complete file
inventory. After comparison it rehashes files and repeats authority checks before
returning evidence. A `PAUSE` marker, changed catalog, missing/expired receipt or
changed binary fails closed. Removing a job requires a newly pinned operator
catalog; the previous host stops serving its old catalog as soon as it changes.
Restarting with the new pin cannot serve a removed job. Coordinator account
deletion and revocation generations remain the final admission authority, so a
late or replayed comparison cannot restore a revoked qualification.

The adapter recomputes the complete fixed-input numerical comparison from the
saved outputs. It does not rerun inference or manufacture execution metadata.
The complete report still says `qualified:false`; only the separately authenticated
registry can create an expiring profile record. Sample compatibility is not
authentic computation of later routine uploads, current Gen4/Scene/protected
authority, or permission to publish a contribution.

The loopback-only server factory exposes just
`POST /object-qualifications/evidence` with a dedicated private bearer secret.
Requests are limited to 4 KiB, responses to 64 KiB, connections to four and active
comparisons to one. Duplicate/ambiguous framing and duplicate/nonfinite JSON fail;
private exceptions, paths and credentials do not enter responses or request logs.
File/comparison work is finite with cooperative elapsed-time checks; this is not
a claim that Python can forcibly interrupt a blocked filesystem operation.

The separate bridge uses its own `OBJECT_SAMPLE_QUALIFIER_ORIGIN` and
`OBJECT_SAMPLE_QUALIFIER_SECRET`; the old native audit key does not enable it.
It requires an approved HTTPS origin and this exact route, sends only validated
identity fields, strips caller credentials, refuses redirects and bounds both
stream sizes and elapsed time to 69 seconds. Late bodies are discarded. It validates
correlation and the numerical-only envelope; the registry independently validates
all numerical/profile/policy fields. No checked-in configuration enables the bridge.
