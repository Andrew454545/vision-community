# Native Community Scene bridge

The native source bridge is implemented and pushed in
[private VISION PR #17](https://github.com/Andrew454545/VISION/pull/17), head
`cf64635a88dcf44ee069e67910a162b9eb478e4b`, dependent on PR #16. It consumes
genuine audited Community Scene completions without claiming they occur in the
owner's local MMA index. The existing owner catalog contracts are preserved.

## Verified behavior

The consumer checks an independently supplied operator catalog fingerprint and
environment, publication receipt, complete Scene bytes and each native output
hash, exact original IDs, camera pose and row mapping. It refuses altered files,
ambiguous membership, wrong resources, path escapes and directory junctions.
Source files remain unchanged. A separately pinned conversion records the road
label change, original/transformed hashes and LF output rule while preserving
all other fields and numerical spellings. It does not infer road names.

Builder, inline sealer and scheduler retain the separate Community authority.
The scheduler requires explicit operator pins and defaults closed. Community
imports remain `productionReady: false`; public admission does not follow from
an operator processing seal. Strict official v6/v7 Gen4 membership, 25m pruning,
exact pano deduplication, capture priority, inline six-view quality and live
protected Main/WAL checks remain mandatory. Dependencies are rechecked at
admission and in the existing pre-work guard.

Windows regression passes **76 of 77 cases**, with zero failures and one existing
POSIX-only executable fixture skipped. Both coverage policies pass the synthetic
builder → sealer → scheduler chain; separate hidden command-line invocations
pass. These are component checks, not real Object inference or Mac acceptance.

## Actual eight-location pipeline

All eight real credited Scene completions pass with their original catalog,
source and snapshot fingerprints. All 76 files in the authentic owner handoff
still match, and its invalid historical import remains refused.

The first real candidate build admitted **zero rows**: the previous validator
input used another catalog location ID, while the original native source used
its original source-row ID. Panorama IDs, countries, generations and all poses
matched. The failed build and its original empty candidate remain preserved.
The identity check was not relaxed and completed validation proofs were not edited.

The new create-only `prepare-community-scene-official-input.mjs` command derives
a fresh validator input from the audited catalog, preserving exact native IDs
and numeric spellings. Original catalog row ordinals are explicitly converted
to the native validator's one-based source rows. Its receipt says **not validated**;
only the actual native validator can establish official coverage afterward.

That repository command passes the pinned native v7 validator: **eight official
rows, eight still-fresh cache hits, zero rejections or new metadata requests**.
The original metadata cache remains unchanged. This reused the original Google
metadata retrieved in the earlier 04:25 UTC validation; a later validation finish
time does not mean a new Google response or extend the underlying freshness.

The real builder then admits **all eight** exact identities, with no exclusions
at the supplied real protected snapshot. Final sealing correctly refuses the
missing matching protected Main/WAL database authority and writes no import seal.
The supplied snapshot is geographic exclusion evidence, not current portable
database authority. No imagery inference, upload, credit or cloud data changed.
