# Object pre-publication integrity — 11 October 2026

The private settlement check now joins the actual quarantined payload, a fresh
native saved-receipt reply and current hosted ownership/coverage. Cached audit
approval alone cannot pass this check. It performs no model inference, database
write, publication, qualification or credit award. It has no public route.

`checkObjectSettlement` verifies the owned upload intent and exact R2 bytes,
refuses privacy fences, decodes every bounded feature lane and checks the full
Object index. Exact panorama, coordinates, heading, pitch, zoom, country and
Generation 4 must agree with current lease rows. Official exact-panorama
coverage must still be fresh; a submitted lease must still be current and own
every quarantined row. Already published, released, cancelled or deleted work
cannot proceed. A busy candidate must finish its existing control operation.

The final native request is a fresh GET correlated to all saved job, assignment,
profile, policy, submission, candidate-manifest, attempt and receipt pins. A
changed receipt, unavailable live protected source or transport failure remains
unavailable. The native service retains its full checks at audit settlement and
startup, with the existing exact file/origin guards on this status read; this
new function does not start another model run or synchronously hash large model
files in the website request.

Current database state is read again after asynchronous payload/native reads.
Cancellation, account deletion, coverage replacement, pose changes or a newer
attempt during the check invalidate it. Database, R2, upstream and response
reads share a maximum 20-second budget. Payload/feature/stream sizes remain
bounded; late native bodies are cancelled. Caller credentials are not forwarded.

The result contains private in-memory candidate bytes, record digests and a
state checksum, with authorization/qualification false and accepted work/credits
zero. **This checksum is not publication authority or an atomic database lock.**
The eventual writer must independently require genuine device qualification and
current protected/runtime/quality authority, then revalidate ownership, receipt,
coverage and deletion fences in its publication/once-only-credit transaction.
It must use the existing owned artifact writer and sanitized public manifest;
the original private candidate object must never be returned to an HTTP client
or copied directly into a public bundle.
