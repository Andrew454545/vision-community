# Scenes first

The first release is **Scene processing and online Scene search**. The user
requested this narrower path to get contributors started sooner. Preserve Object
work for a later release; it must not keep taking priority over Scene launch work.
Windows and Apple-silicon Mac remain supported targets. Release each supported
profile only with its actual qualification and installation evidence.

Keep anonymous accounts, exclusive assignments, local resumable processing,
banked credits, contributor-only online search and saved paid-result recovery.
Use the approved qualification-based Scene upload policy and the $10/month
processing envelope plus separate R2. Routine uploads do not need native
recomputation. The existing audited mode remains distinct.

## What is already available

- [Real Windows Scene work and earned-credit search](WINDOWS_SCENE_COHORT_20261010.md):
  fixed 112-location qualification, eight fresh contributed locations and exact
  paid-result recovery. The Mac fixed-input reference and completed thread matrices
  are comparison evidence; they do not replace a fresh Mac installation check.
- [Qualified routine Scene uploads](QUALIFIED_SCENE_UPLOADS.md), exclusive leases,
  upload integrity, once-only credit and offline snapshot/financial recovery in source.
- [Queued online search](HYBRID_SEARCH_QUEUE.md) and the
  [finite Scene executor](NATIVE_QUEUED_SEARCH.md), with bounded claims, spending
  reservations, shutdown and saved result recovery in source.
- Background checkpoint/restart controls and the requested Medium/day,
  Maximum/midnight–6 a.m. schedule. Only qualified parallel profiles may run.
  A powered-off or sleeping computer resumes work when running again.

Reuse this evidence. Repeat a check only for changed inputs/behavior, an unresolved
failure or an actual release gate. Local synthetic checks do not establish live
acceptance of the new hybrid deployment.

activation are external dependencies, not engineering decisions to fabricate.
No full public-launch date is established by this scope change.

Start with a bounded contributed Scene corpus. Million-location scaling and
additional platform/performance refinements can follow without making unsupported
capacity promises or overrunning the current supported limits.

## Deferred

Object qualification, fresh official Gen4/protected Object admission, Object pool
preparation, Object search, Objects/Both onboarding and Object endurance are **not
first-release gates**. Keep their endpoints/capabilities closed and retain their
source, private data and evidence. Do not spend the next engineering runs on these
components unless necessary to isolate or protect the Scene release.

The [five acceptance gates](PRODUCTION_ACCEPTANCE.md) now apply to the Scene-only
first release. Their Scene trust, finances, privacy, recovery, trusted downloads,
cost controls and endurance requirements remain. Full Scenes/Objects/Both acceptance
is a later milestone. No cloud deployment, task restart, paid work, account change,
destination-specific private transfer or Actions dispatch is authorized by this
product-priority change.
