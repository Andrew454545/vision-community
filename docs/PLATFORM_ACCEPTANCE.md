# Windows and Mac release scope

The finished application must let Windows and Mac users choose **Scenes**,
**Objects** or **Both** through the same simple guided setup. This is required
project scope, not a claim that these combinations are available today.

| Computer and work | Evidence available | Still required |
| --- | --- | --- |
| Windows Scenes | Guided maintainer preview; actual native calibration and limited staging contribution/search tests. | Qualified distributed release, trusted live input identity, accepted background work and extended recovery/endurance. |
| Mac Scenes | Controlled Mac reference and native ownership; actual private Python/source/window; guarded per-user background controls and finite scheduled recovery pass on Apple silicon. | Guided native download/dependencies/inference, exact qualified runtime, accepted contributions, active-work handover, actual sign-in/restart and clean-device/endurance checks. |
| Windows Objects | Portable native pilot with all three models; small frozen thread study and native structural verification. | Guided setup/qualification, published validated runtime, broader reference comparison, trusted Gen4 audit/publication and background recovery. |
| Mac Objects | Original command-based integration and Mac runtime manifest. | Guided setup/qualification, current distributed runtime, broader native comparison, trusted Gen4 audit/publication and background recovery. |

None of these rows is a completed production release. Linux inference evidence
supports backend portability; it does not replace Mac or Windows user testing.
The [private Mac starter](MAC_PRIVATE_STARTER_20261004.md) is a maintainer preview;
its bootstrap/window evidence does not establish native processing or admission.
The [Mac background foundations](MAC_BACKGROUND_FOUNDATIONS_20261004.md) add
actual process-owned sleep-request evidence and a startup/recovery contract.
The [Mac background controls](MAC_BACKGROUND_CONTROLS_20261004.md) now verify
registration, schedule changes, pause/resume, immutable startup checks and
private-window ownership in an actual Mac fixture. Accepted native work and
the complete unattended release remain unqualified.

## What every row must pass

- A beginner downloads and opens VISION without installing Python or Git, copying
  commands, changing security settings or obtaining administrator access.
- Setup selects the exact runtime/model files for the computer and chosen work.
  It verifies checksums and resumes interrupted downloads. Optional model files
  are downloaded when their lane is selected; Both prepares both sets.
- Scenes and Objects have their own reference comparison and trusted admission.
  Scene approval must not grant object approval, or vice versa. Andrew's native
  results remain the reference; measured differences need justified limits.
- Each lane processes an actual accepted batch, publishes only contributed
  results and earns its correct banked credits once. Lost replies, restart and
  account recovery must not lose earned work or duplicate awards.
- Both uses a durable scheduler with measured shared CPU, memory and storage
  limits. It must not start two competing native writers or treat unverified
  extra threads as approved. Maximum selects the fastest verified configuration
  available on that computer; day/night pacing remains adjustable.
- Background work survives sign-out/restart through the OS's supported startup
  mechanism, retains unfinished batches and retries temporary outages with
  persisted delays. Permanent trust failures preserve a report and stop.
  A sleeping or powered-off computer resumes after waking/sign-in; it cannot
  compute while asleep or off. Validate this on each OS.
- Object assignments and search remain restricted to independently evidenced
  official Generation 4 coverage on every platform. A client label is not proof.
- Online searches use banked credits and only verified user contributions.
  Anonymous account recovery/deletion and private failure reports work for
  Scenes, Objects and Both without exposing credentials or names.

## Architecture and release evidence

The Windows preview targets Intel/AMD 64-bit PCs; the existing Mac runtime
manifest targets Apple silicon. Intel Macs and Windows on ARM require their own
compatible builds, dependency and inference checks before being called supported.
Do not silently use another architecture's binary or assume translation provides
the same runtime identity, precision, performance or trusted qualification.

Record the OS/architecture, immutable download and checksum, runtime/model/helper
pins, exact lane/thread settings, comparison results, accepted publication/credit
receipts and clean-device/background observations for every supported build.
Keep failed attempts. Check off a row only when all its requirements have
evidence in [production acceptance](PRODUCTION_ACCEPTANCE.md).
